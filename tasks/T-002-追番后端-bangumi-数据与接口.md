# T-002 追番后端：bangumi 数据源 + 追番数据模型 + 接口

## 目标

让灵搜后端能「记住用户的追番列表」并通过 bangumi（番组计划）检测哪些番剧已更新，
为前端追番界面与进站提醒提供接口。

## 验收标准

- [ ] 新增追番数据模型并完成建表（字段至少含：bangumi subject_id、番剧标题、封面、
      已看话数、最后检测时间、创建时间）
- [ ] 提供「按番剧名搜索」接口：调 bangumi 返回候选 subject 列表，供前端添加时选择
- [ ] 提供追番列表 CRUD 接口（列表 / 添加 / 删除）
- [ ] 提供「更新检测」接口：返回哪些追番有新话（bangumi 最新正片话数 > 已看话数）
- [ ] 提供「标记已看」接口（更新已看话数，用于消除红点）
- [ ] bangumi 请求带 `User-Agent`；网络失败时返回明确错误文案，不吞成空结果
- [ ] 实跑验证：搜番剧名 → 添加 → 检测更新 → 标记已看，全链路返回正确

## 约束条件

- **基本约束**（全局，见 `tasks/README.md` 第五节）：减少不必要的内容生成——
  不新增需求外的字段、端点、文案；不写「产品自我介绍」式注释。
- **本任务约束**：
  - bangumi 是「数据源」，**不要塞进 `platforms/`**（那是搜索平台适配器），
    放 `services/`（或新建 `providers/`）独立成模块；
  - 「更新检测」判定必须明确（对比已看话数与 bangumi 最新正片话数），不许用估算值；
  - 追番数据存现有 SQLite（复用 `app.db`），**不动** `models/account.py` 及账号逻辑；
  - 网络访问：本机环境复杂，bangumi 若需代理要**显式指定**，不依赖 `trust_env`。

## 问题记录（执行 Agent 回写）

- [2026-10-18] **数据源不可达（已由使用者决策变更）**：bangumi 三条通路全断——
  直连 ConnectTimeout（DNS 被污染，`api.bgm.tv` 解析到 157.240.9.36 Facebook 网段）、
  会话代理 49888/49688 返回 **502**（白名单代理，github/bilibili 放行、bgm.tv 不放行）、
  本机 7890/10809/1087 均未监听。
  → 使用者决定**改用 agedm.io（Age 动漫）**：`https://api.agedm.io/v2` 直连可用（约 1.2s），
  **无需代理**，但证书链不完整，必须 `verify=False`。
- [2026-10-18] 使用者决策：① 模型**保留 `subject_id` 字段名**（实际存 agedm 的 AID）；
  ② 证书校验**做成可配置开关**（`AGEDM_VERIFY_SSL`，默认关闭以适配当前站点）。
- [2026-10-18] 本地环境：playwright `connectOverCDP` 连 127.0.0.1 会被会话代理拦成 502，
  本地回环需 `unset *_proxy` + 设 `NO_PROXY`；本机无 Chrome，浏览器用 Edge。
- [2026-10-18] **agedm 的两个坑（已处理）**：
  1. 站点证书链不完整，`verify=True` 直接 CERTIFICATE_VERIFY_FAILED，必须关闭校验；
  2. **搜索接口不返回 `playlists`**，因此 `uptodate` 写成「已完结」的条目
     （如「23:00 已完结」）在候选列表里拿不到话数（显示 0）。详情接口才有集数列表。
     已在 `add_follow` 走详情重算解决（实测：候选 0 话 → 添加后正确取到 24 集）；
     候选阶段显示 0 属接口信息缺失，非 bug。
- [2026-10-18] **集数解析必须兼容多种写法**：真实数据里出现「第03集」「第12集(完结)」
  「01:00 第03集」「全24集」「共12话」「更新至12」「23:00 已完结」「PV」。
  只按「第N集」解析会让完结番全部变成 0 话。已覆盖 11 组用例。
- [2026-10-18] **验收脚本未入库**：按基本约束第 1 条（不加没被要求的测试文件），
  全链路验收脚本放在 `.workbuddy/verify-anime.py`，仓库内不新增测试文件。
