# T-003 追番前端：追番管理界面 + 进站更新提醒 + 点击跳转

## 目标

在灵搜前端落地追番的完整用户闭环：能管理追番列表、进站时看到更新提醒、
点追番条目自动搜索该番剧并直接看结果。

## 验收标准

- [ ] 追番管理界面：展示追番列表（封面 / 标题 / 最新话数 / 更新状态），支持添加
      （按番剧名搜索、从候选里选择）和删除
- [ ] 顶栏新增追番入口；有更新时入口显示红点
- [ ] 进站时若存在更新番剧 → 顶部横幅提示，点击进入追番列表
- [ ] 点击追番条目 → 自动以该番剧名触发一次搜索，直接展示结果列表
- [ ] `cd frontend && npx tsc --noEmit && npm run build` 通过
- [ ] 实跑首屏（:8000 + :5173）：追番入口、横幅、跳转搜索均正常

## 约束条件

- **基本约束**（全局，见 `tasks/README.md` 第五节）：减少不必要的内容生成——
  UI 文案能短则短，不加没被要求的说明段落、按钮、弹窗。
- **本任务约束**：
  - 复用 `api/client.ts` 的封装风格，追番类型定义与接口调用收进该模块或独立类型文件；
  - 视觉与灵搜现有风格一致（沿用 ink-* 色板、surface 等既有 class），不另立一套主题；
  - 「点击自动搜索」复用现有搜索逻辑/状态，**不要另写一套搜索流程**；
  - 依赖 T-002 后端接口（`/api/anime/*`），联调前先确认后端接口已就绪。

## 问题记录（执行 Agent 回写）

- [2026-10-18] **本任务验收标准第 4 条已由使用者变更**：原为「点击追番条目 → 自动以
  该番剧名触发一次搜索」，改为「点击追番条目 → 从 agedm 获取资源」。
  原因：追番数据源已是 agedm（T-002 换源），跳本地搜索对不上番剧资源。
- [2026-10-18] 使用者决策：① 界面用**独立路由页 `/anime`**（非浮层）；
  ② 点击条目**应用内 iframe 嵌入** agedm 页面。
- [2026-10-18] **iframe 嵌入遇到硬阻碍（实测）**：agedm 返回
  `X-Frame-Options: SAMEORIGIN`，浏览器直接拒绝跨站嵌入：
  `Refused to display 'https://www.agedm.io/' in a frame because it set 'X-Frame-Options' to 'sameorigin'`。
  实测「剥掉 XFO 后」外层详情页能完整渲染（标题/简介/集数按钮/播放源切换都在），
  **但播放器是嵌套的第二个 iframe**，点集数后同样因 XFO 被拦成一屏空白
  （`<base href>` 使相对路径解析到 www.agedm.io，又被自己的 XFO 拒绝）。
- [2026-10-18] 使用者决策：选 **B 路线 —— 只代理外层页**。
  应用内可浏览番剧详情与集数列表，**播放仍需到 agedm 站内**（界面需明确提示，
  不能假装能播 —— 否则用户点集数看到空白会以为是我们坏了）。
  完整代理播放器 + m3u8 流属独立工程，建议另发任务。
- [2026-10-18] 可对齐的既有先例：仓库已有 YouTube 的同款处理
  （`embed.py:/platforms/youtube/embed` + adapter 的 `fetch_embed_html`，
  注入 `<base>` 与 XHR 转发补丁），agedm 代理沿用同一模式。
- [2026-10-18] **验收标准第 4 条已按变更后的口径验收**：不再是「跳本地搜索」，
  而是「点击条目 → 从 agedm 获取资源」。实测结果：能在应用内 iframe 看到
  agedm 的番剧详情与集数；**播放必须到站内**（原因见上）。
- [2026-10-18] 给发布者的建议（新基本约束候选）：
  **「嵌入第三方页面」类需求，动手前应先验证目标站点的 X-Frame-Options /
  CSP frame-ancestors，以及播放器等是否还有嵌套 iframe。**
  本次若不做这一步，会写出一个「看着能嵌、点播放全白」的半成品。
- [2026-10-18] 另一个候选约束：**换数据源时，要连带核对该源的页面嵌入策略与
  资源结构**（agedm 用 XFO + 嵌套播放器，和 bangumi 完全不同），
  否则后端能用的结论会掩盖前端「能用一半」的问题。
